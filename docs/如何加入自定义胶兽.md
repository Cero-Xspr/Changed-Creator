# 如何加入自定义胶兽（Changed Creator 使用说明）

> **Changed Creator** 是一个运行时加载器 mod（Forge 1.20.1，依赖 Changed: Minecraft Mod v0.15.7）。
> 你不需要写任何 Java 代码、不需要装 JDK/Gradle：写好一个 JSON 放进指定文件夹，重启游戏，新胶兽形态就注册好了，可以用 `/transfur` 直接变身。

## 1. 当前状态（已部署，全部功能实测正常）

| 内容 | 位置 | 说明 |
|---|---|---|
| 加载器 mod | 见下方「三处环境部署」 | 含贴图扩展（外观覆盖），全部功能实测正常 |
| 示例胶兽 | `config/changedcreator/forms/red_wolf.json` | 示例：红狼形态（复用 dark_latex_wolf_male 实体） |
| 示例外观 | `config/changedcreator/appearance.json` | 黄色演示贴图（texture）+ 红色 tint |
| 示例配方 | 内嵌于 jar（`data/changedcreator/recipes/form_red_wolf.json`） | 灌注台配方：latex_base + 红染料 → 红狼 |

**已验证的外观覆盖效果**（2026-08-22 实测）：
- ✅ 狼本体：自定义贴图（黄）
- ✅ 第一人称手：与本体一致的贴图
- ✅ 转换动画：保持原版流程（人形显示玩家原皮肤，不被自定义贴图污染）
- ✅ 转换动画 latex 覆盖色：tint（红）
- ✅ 背包/技能轮盘 UI 色：tint（红）
- ✅ 滴落粒子：跟随本体贴图
- ✅ 热加载：`appearance.json` 改色/贴图配置约 2 秒生效；贴图文件改完 `/reload`

| 环境 | 版本 | mods 位置 |
|---|---|---|
| lsb4（主整合包） | Forge 47.4.16 | `.../versions/lsb4/mods/` |
| 轻量测试环境 | Forge 47.4.16（新建版本） | `LAZYFURPACK3.5.3/.minecraft/versions/1.20.1-Forge_47.4.16/mods/` |

三个环境的 `config/changedcreator/` 均已配置（forms + appearance）。轻量环境只装 3 个 mod（changed + changedcreator + mixinextras），启动快，适合调试；`downloadPatreonContent` 已设为 `false`（避免启动时下载 patreon 内容卡死，见第 7 节）。

启动游戏后：
- 日志应出现 `Registered custom latex form red_wolf -> base changed:dark_latex_wolf_male` 与
  `VERIFY: transfur variant changedcreator:red_wolf present in registry = true`
- 游戏内执行 `/transfur @s changedcreator:red_wolf` 即可变身（需要作弊权限，单机可开）。

## 2. 快速开始：加一个你自己的胶兽

1. 在 `config/changedcreator/forms/` 新建一个 JSON（文件名随意，如 `my_creature.json`）
2. 按下面的字段表写内容（`id` 和 `base_entity` 必填）
3. 重启游戏（或重新进存档）——新形态自动注册

```jsonc
{
  "id": "my_red_wolf",                      // 形态 id → changedcreator:my_red_wolf
  "base_entity": "changed:dark_latex_wolf_male", // 复用的基础胶兽实体（决定外观/模型）
  "transfur_mode": "replication",           // 可选: replication | absorption | none
  "properties": {                            // 可选：游戏属性（详见字段表；也接受 camelCase 写法）
    "can_climb": true,
    "night_vision": true,
    "double_jump": true
  },
  "abilities": ["changed:toggle_night_vision"] // 可选：能力 id 列表
}
```

4. （可选）加配方：在数据包里放 `data/<任意命名空间>/recipes/form_xxx.json`：

```json
{
  "type": "changed:infuser",
  "ingredients": [
    { "item": "changed:latex_base" },
    { "item": "minecraft:red_dye" }
  ],
  "form": "changedcreator:my_red_wolf"
}
```

## 3. JSON 字段参考

| 字段 | 必填 | 取值 | 说明 |
|---|---|---|---|
| `id` | ✅ | `[a-z][a-z0-9_]{0,63}` | 形态 id，完整 id = `changedcreator:<id>`，`/tf` 用 |
| `base_entity` | ✅ | 资源 id | **已注册的 Changed 胶兽实体**，如 `changed:dark_latex_wolf_male`、`changed:white_latex_wolf_female`、`changed_addon:...`（Changed Addon Plus 的实体）等。决定外观/模型/纹理/基础属性（含阵营、步距、跳跃） |
| `transfur_mode` | | `replication`/`absorption`/`none` | 转化他人的方式 |
| `abilities` | | id 数组 | 授予的能力，如 `changed:toggle_night_vision`、`changed:create_cobweb` |
| `properties.gills` | | bool | 水陆两栖呼吸 |
| `properties.can_climb` | | bool | 爬墙、无视蛛网 |
| `properties.night_vision` | | bool | 夜视 |
| `properties.reduced_fall` | | bool | 减伤坠落 |
| `properties.glide` | | bool | 翅膀：弱化创造飞行 + 鞘翅滑翔 |
| `properties.double_jump` / `extra_jumps` | | bool / int | 空中二段跳 / 跳跃次数 |
| `properties.quadrupedal` | | bool | 四足（影响护甲穿戴） |
| `properties.no_legs` | | bool | 无腿形态 |
| `properties.disable_items` | | bool | 禁用物品/攻击/交互 |
| `properties.hold_items_in_mouth` | | bool | 只能嘴叼一件物品 |
| `properties.camera_z_offset` | | number | 摄像机前后偏移（格） |
| `properties.sound` | | 资源 id | 变身音效，如 `changed:poison` |

完整 schema 见项目 `schema/latex-form.schema.json`（JSON Schema 校验用）。

## 4. 外观限制（重要）

当前实现（路线 B1：复用现有实体）下，**新形态的外观 = 基础实体的外观**（模型、纹理、动画都复用）：
- ✅ 可以自定义：全部 gameplay 属性、能力、转化模式、配方、独立形态 id
- ✅ **已支持外观覆盖**：变色（tint）与自定义贴图（见第 5 节）
- ❌ 尚不能：全新模型/新骨骼（那需要写 Java addon 或走「自定义模型扩展」路线，见选型报告；外观配置里已预留 `model` 字段给未来版本）
- 已知可用的实体资源：`changed` 模组有 100+ 胶兽实体（dark/white latex 系列、wolf、dragon、shark、bee、crocodile……），Changed Addon Plus 另有 30+（snow fox、kitsune、puro、calico cat……）。换皮 + 自定义属性通常够用。

## 5. 自定义外观（变色 / 贴图）

配置文件：`config/changedcreator/appearance.json`（**可选**，没有就全部用基实体外观）。
这个文件和 `forms/` 目录一样，都是**游戏目录下的外部文件**——不打包在 mod 里，你可以随时增删、改完**不用重启游戏**（见第 6 节热加载）：

```jsonc
{
  "changedcreator:red_wolf": {          // 键 = 完整形态 id
    "texture": "changedcreator:textures/entity/red_wolf.png", // 可选：自定义贴图
    "tint": "#ff3333"                    // 可选：变色（十六进制 RGB）
  }
}
```

### 5.1 变色（最简单，立刻生效）
只写 `tint` 字段，例如上面把 red_wolf 染成红色。对**实体形态**（召唤/自然生成的胶兽）立即生效；重启游戏后对玩家形态也生效。改色不需要画图。

### 5.2 自定义贴图（换皮）
1. 从 Changed 模组 jar 里复制基实体的贴图做底稿（如 `Changed-m1.20.1-v0.15.7-all.jar` 内的 `assets/changed/textures/entity/dark_latex_wolf_male.png`），用图片编辑器按原 UV 布局改色/改花纹，另存为 `red_wolf.png`
2. 把 PNG 放进资源包：`.minecraft/resourcepacks/<你的包名>/assets/changedcreator/textures/entity/red_wolf.png`（并在 `pack.mcmeta` 声明 `pack_format: 15`），游戏里启用该资源包
3. 在 `appearance.json` 里给对应形态加上 `"texture": "changedcreator:textures/entity/red_wolf.png"`
4. 重启游戏

> 注意：`texture` 指向的资源不存在时会显示紫黑棋盘格（缺失纹理）——先把贴图放进资源包再引用。玩家形态与实体形态都支持换贴图（实测确认后生效）。

### 5.3 自定义模型（换骨骼/新建模）——预留
全新体型（不是换皮）需要 Java：Blockbench 建模 → `AdvancedHumanoidModel` 子类 + 渲染器 + 实体。这是选型报告的路线 A/C，目前不在 JSON 能力范围内；`appearance.json` 已预留 `model` 字段，未来版本将支持按形态挂载自定义模型层。

## 6. 热加载与联机（重要）

### 6.1 什么能热加载、什么必须重启

| 改动 | 生效方式 | 说明 |
|---|---|---|
| 颜色 / 贴图配置（`appearance.json`） | **自动热加载**（约 2 秒内生效） | 改 `tint`/`texture` 字段后无需任何操作 |
| 贴图文件（`red_wolf.png` 等 PNG） | 游戏内执行 `/reload` | 替换贴图文件后重载资源即可 |
| 形态定义（`forms/*.json` 新增/改 id/base_entity/属性/能力） | **必须重启游戏** | MC/Forge 的注册表在启动时冻结，运行时无法注册新形态——这是引擎机制限制，非本 mod 缺陷 |

> 日常流程建议：**配色/换皮**随时改随时生效；**加新形态或改形态属性**才需要重启。

### 6.2 联机（多人）分工

- **形态（变体）**：服务端启动时注册 → 自动同步给所有客户端 ✓。**服务端和每个客户端都要装** `changedcreator`（+ `changed`）。
- **贴图 / 颜色配置（appearance.json + PNG）**：这是**客户端渲染**用的资产，服务端数据包不会自动下发。联机时：
  - 每个玩家的客户端各自配置自己的 `config/changedcreator/appearance.json`，或
  - 把贴图打进 mod jar（随 mod 分发，所有人都一样）
- **数据包（datapack）说明**：MC 的数据包是服务端世界数据（放 `saves/<世界>/datapacks/`），而本 mod 的形态读取发生在游戏启动早期（`config/` 目录，注册表冻结前），因此**暂不支持从数据包加载形态**——请继续使用 `config/changedcreator/` 目录（它本身就是游戏目录下的外部文件）。

## 7. 常见问题

- **日志出现 `base_entity 'xxx' is not used by any existing transfur variant`（warning，不报错）**
  说明该实体当前没有对应变体。它仍是 Changed 实体就能用；若引用了普通实体（如 `minecraft:zombie`），形态可能异常，请改用已注册的胶兽实体。
- **改 JSON 后不生效**：形态在启动时读取，需重启游戏/重进存档。
- **加多个形态**：一个 JSON 一个形态，`id` 不能重复，文件名随意。
- **卸载**：删除 `mods/changedcreator-1.0.0.jar` 与 `config/changedcreator/` 即可，存档中的变身会随模组移除而失效（同 Changed 其他形态行为）。
- **开发环境提示**：`./gradlew runServer`（dev 环境）会因 Changed 模组自身的 mixin refmap 与 dev 映射不兼容而失败，这是 Changed 0.15.7 的问题，与 changedcreator 无关；玩家环境（production）不受影响。

## 8. 已解决的坑（开发记录）

- **启动卡死（概率性）**：Changed 启动时下载 patreon 内容（GitHub raw），网络慢/被墙时超时卡死（关网络反而能继续）。修复：`config/changed-common.toml` 设 `downloadPatreonContent = false`。
- **玩家模型被自定义贴图污染**（转换动画的人形显示黄狼贴图）：根因是渲染目标实体没区分——转换动画人形渲染的是 **Player 实体**（本应显示玩家皮肤），而贴图覆盖错误地作用到了 Player。修复：`LivingEntityRendererMixin` 对 `entity instanceof Player` 永不覆盖，仅变体实体实例（ChangedEntity）应用自定义贴图。
- **第一人称手黑色**：手部渲染走 `FormRenderHandler.renderHand`（独立路径），用「实体→玩家」映射（renderForm 时记录变体实体归属玩家）反查后覆盖。
- **转换动画颜色**：latex 覆盖色走 `TransfurVariantInstance.getTransfurColor()`（tint），UI 色走 `getColors()`——两条独立通道，需分别 mixin。
- **粒子颜色**：`LatexParticlesLayer.createNewDripParticle` 从贴图像素采样（异步，不在渲染栈内），用实体→玩家映射解决。
