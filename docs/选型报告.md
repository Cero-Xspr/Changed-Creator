# 自定义胶兽方案选型报告

> 目标：为 Changed: Minecraft Mod（v0.15.7，Forge 1.20.1）提供一个**比手写 Java addon 更简易**的「加入自定义胶兽」方式。
> 本报告基于对本地模组 jar 的字节码核对、官方 Wiki 文档、官方 addon（Changed Vanilla）源码与社区 addon（Changed Addon Plus 2.8.2b）的解剖。

## 1. 背景事实（探索证据）

### 1.1 官方扩展 API 存在且完整

Changed 官方设计了完整的 addon API（Wiki 有 10 页文档 + 2 个教程）：

| 能力 | 类/接口 | 本地 v0.15.7 确认 |
|---|---|---|
| 变体注册表 | `ChangedRegistry.TRANSFUR_VARIANT` + `createDeferred(modId)` | ✅ 存在 |
| 变体构建器 | `TransfurVariant.Builder.of(EntityType).build()`，可配 faction/gills/canClimb/glide/extraJumps/transfurMode/visionType/noLegs/itemUseMode/quadrupedal/rideable/addAbility 等 42 个 public 成员 | ✅ 存在 |
| 实体父类 | `ChangedEntity`（抽象 `getTransfurMode()`；可覆盖 `getTransfurColor`/`getSelfVariant`/`getHairColor`） | ✅ 存在 |
| 渲染 | `AdvancedHumanoidRenderer` + `AdvancedHumanoidModel` + `HumanoidAnimator` + `AnimatorPresets`（catLike/wolfLike 等预设） | ✅ 存在 |
| 查询 | `ProcessTransfur.getPlayerTransfurVariant` / `ifPlayerTransfurred` | ✅ 存在 |
| 同化（自然转化） | `ProcessTransfur.GatherMobAssimilationsEvent` + `EntityAssimilationBehavior` + `TransfurDecider` | ✅ 存在 |
| 配方（纯数据） | `data/<mod>/recipes/*.json`，`"type":"changed:infuser"` + `"form":"<modid>:<variant_id>"` | ✅ 存在（Changed Vanilla 实证） |
| 变体 tag（纯数据） | `data/changed/tags/changed/latex_variant/{break_items_on_tf,can_sleep_on_pillows,masked,temporary_only}.json` | ✅ 存在 |

### 1.2 版本差异（v0.15.7 与新版 Wiki 教程不同）

- 阵营 `LatexType` 在 v0.15.7 是 **abstract class**，引用方式为 `ChangedLatexTypes.NONE/DARK_LATEX/WHITE_LATEX.get()`（新版教程的 `LatexType.NEUTRAL` 常量不存在）。
- 实体分类直接用原版 `MobCategory.MONSTER/CREATURE`（新版教程的 `ChangedMobCategories.CHANGED` 不存在）。
- 实现必须按 v0.15.7 实际 API 编写（Changed Vanilla 的 gradle.properties 锁定 `changed_version=0.15.7`，可作为完全匹配的范本）。

### 1.3 官方 addon「Changed Vanilla」= 最完整范本（MIT）

- 工程：Forge MDK 1.20.1 + Java 17 + `fg.deobf("net.ltxprogrammer.changed:Changed-m1.20.1-f47.4.0:v0.15.7"){changing=true}`（maven: `https://ltxprogrammer.github.io/maven/`）。
- 14 个胶兽实体，每个 = 1 个实体类（构造器 + `setAttributes(AttributePresets.xxx)` + `getTransfurMode` + `getTransfurColor`）+ 1 个模型类 + 1 个渲染器类 + 1 个变体注册。
- 实体注册：`EntityType.Builder.of(X::new, MobCategory.MONSTER).clientTrackingRange(10).sized(w,h)` + `ChangedEntities.registerEntityColor` + `ForgeSpawnEggItem`。
- 变体注册：`DeferredRegister<TransfurVariant<?>> REGISTRY = ChangedRegistry.TRANSFUR_VARIANT.createDeferred(modid)`；`REGISTRY.register(name, builder::build)`。
- 渲染注册：`ChangedEntityRenderers.registerHumanoid(event, type, Renderer::new)`（Changed 提供辅助方法）。
- 数据：`form_latex_*.json` 配方纯数据引用变体；纹理 `assets/<modid>/textures/entity/latex_xxx.png`；模型源为 Blockbench `.bbmodel`。

### 1.4 社区 addon「Changed Addon Plus 2.8.2b」（用户已安装）

- 同样走**编译期 DeferredRegister 注册**（无运行时数据加载先例），但规模更大（1488 个类）：自有实体 30+（`net.foxyas.changedaddon.entity`）、自有 ability 树、tamed-latex 机制、patchouli 手册、变体 tag 封装（`ChangedAddonTags$TransfurVariants`）。
- 它证明了这套 API 能支撑大型内容扩展，但它本身不提供"简易加入"能力——新胶兽仍需写 Java。
- 许可注意：modrinth 标注 GPL-3.0-or-later（mods.toml 写 MIT，以 modrinth 声明为准），**不适合作为衍生改造基础**（会传染 GPL）；官方 Vanilla（MIT）才是干净的模板。

## 2. 候选路线

### 路线 A：代码生成器（CLI 脚手架）
用户写一份胶兽定义（YAML/JSON），工具按 Changed Vanilla 模式**生成完整可编译的 addon 工程**（实体类/模型/渲染器/变体注册/build.gradle/资源/配方），再交给用户 `./gradlew build`。

- 优点：能力完整（新模型/新实体/新属性/新能力/同化机制全支持）；产出标准 addon；一次生成可反复修改。
- 缺点：**仍需 JDK 17 + Gradle + 联网拉取 Forge/Changed 依赖**才能编译；定义 → 游戏内生效有编译环节；模型仍需用户在 Blockbench 里做。

### 路线 B：运行时 JSON 加载器 mod（一个通用 mod 读取 JSON 定义注册变体）
**B1（推荐）— 复用现有实体**：加载器在 mod 加载阶段读 JSON，对**已注册的 Changed 实体**（如 `changed:dark_latex_wolf_male`）用 `TransfurVariant.Builder.of(实体)` 注册新变体。
- 不需要新实体类/模型/渲染器（注册层面对 `Builder.of` 而言只需一个 `Supplier<EntityType<T>>`）。
- 新形态 = 基实体外观 + 可自定义属性（跳跃/呼吸/攀爬/滑翔/能力/阵营/步距/鞍等全部 Builder 字段）+ 独立变体 id（`/tf @s modid:xxx` 可用）+ 独立配方（数据包）。
- **局限（关键风险）**：纹理/模型绑定实体渲染器，变体本身无 texture 字段——新形态外观默认等于基实体（能否换色取决于 `getTransfurColor` tint 等机制，需阶段 3 首日验证）。

**B2 — 运行时注册全新实体**：加载器动态 `Registry.register` EntityType + 属性 + 渲染器。
- 优点：外观可完全自定义。
- 缺点：Forge 事件时序（属性创建、渲染注册都在 mod 加载期，运行时补注册需混入/事件重放），复杂度与崩溃风险高；**不建议**作为首版。

### 路线 C：混合
B1 为主（JSON + 数据包，免编译），预留「高级扩展」出口：需要全新模型的用户，工具可生成「模型/渲染器单独补丁」的最小 addon 骨架（只写模型和渲染器两个类，其余复用加载器的变体注册路径）。

## 3. 对比矩阵

| 维度 | A 生成器 | B1 运行时加载器（复用实体） | B2 运行时加载器（新实体） |
|---|---|---|---|
| 加入新形态的复杂度 | 写定义 + 编译 | **只写 JSON + 放纹理** | 高（运行时注册） |
| 是否需 JDK/Gradle/联网编译 | 需要 | **不需要** | 不需要（但代码复杂） |
| 新模型/新外观 | 完整支持 | ✗（继承基实体外观） | 完整支持 |
| 属性/能力自定义 | 完整 | 完整（Builder 全字段） | 完整 |
| 独立变体 id / `/tf` 可用 | ✅ | ✅ | ✅ |
| 配方（infuser）数据驱动 | ✅ | ✅ | ✅ |
| 同化机制（原版生物变胶兽） | ✅ | ✅（引用现有实体） | ✅ |
| 维护成本 | 模板升级成本 | 低（单 mod） | 高 |
| 许可风险 | 无（自研） | 无（自研） | 无（自研） |
| 技术风险 | 低 | **中（外观限制未验证）** | 高 |

## 4. 推荐

**主线：路线 B1（运行时 JSON 加载器 mod，复用现有实体）**，同时预留 C 的扩展出口。

理由：
1. 完全命中用户目标「更简易方式加入自定义胶兽」——JSON 定义 + 数据包 = 免编译、免建模，加入一个形态只需 1 个 JSON + 1 个配方（可选）。
2. 注册层已被官方 API 验证可行（`Builder.of` 接受任意已注册 Changed 实体的 EntityType；配方/变体 tag 都是数据）。
3. 官方范本（Vanilla，MIT）与本地 API 版本（0.15.7）完全匹配，加载器本体可安心自研（MIT 无 GPL 负担）。

**阶段 3 首日必须验证的风险点**（决定 B1 是否成立）：
- 变体外观：新变体渲染时是否仍显示基实体纹理；`getTransfurColor`/`LatexParticlesLayer`/资源覆盖能否实现可接受的换色/换肤（如能 → B1 立即可交付；如不能 → 退化为「B1 + 最小模型补丁 addon」即路线 C，或评估 B2）。
- 运行时注册时机：Forge `DeferredRegister` 需在 mod 构造时注册；加载器在 `FMLCommonSetupEvent` 或 `RegisterEvent` 中动态注册变体是否被 Changed 接受（Changed 的变体注册表是 Forge registry，`RegisterEvent` 动态注册标准可行）。

## 5. 交付形态（B1 路线预览）

```
changed-creator/
├── loader/                     # 加载器 mod 工程（Forge MDK 1.20.1 + Changed 依赖 v0.15.7）
│   ├── ...                     # 主类：读 JSON → Builder 注册变体
│   └── build.gradle
├── schema/                     # 胶兽 JSON 定义 schema（JSON Schema 文件 + 字段文档）
├── examples/                   # 示例胶兽定义（含配方、tag）
├── docs/                       # 本报告 + 《如何加入自定义胶兽》说明
└── pack/                       # 可直接放进 .minecraft 的数据包/资源包（示例）
```

胶兽定义 JSON 草案（示意）：
```jsonc
{
  "id": "my_red_wolf",                        // 变体 id → modid:my_red_wolf
  "name": "Red Wolf Form",
  "base_entity": "changed:dark_latex_wolf_male", // 复用的基础实体
  "faction": "dark_latex",                    // ChangedLatexTypes
  "properties": {
    "stepSize": 0.7, "jumpStrength": 1.2,
    "gills": true, "canClimb": true,
    "nightVision": true, "quadrupedal": false
  },
  "abilities": ["changed:toggle_night_vision"],
  "color": 0xe74c3c                          // getTransfurColor tint（待验证生效方式）
}
```
